> **状态：已实现（2026-10-23）**，代码见第十一节「实现记录」。

## 一、需求来源与目标

销售在跟单过程中会丢单，需要把「为什么丢」结构化沉淀下来，并能从多个角度分析丢单原因，
反向驱动产品、报价策略与销售动作。

- **填写**：销售人员逐单登记（输单登记页）。
- **列表**：输单台账，可按时间/维度筛选、导出。
- **分析**：按时间段从多角度统计（类型、阶段、行业、规模、预算匹配、业务员、趋势、交叉）。

| 9 | 最终报价（元） | 数字 | 否 | — | DECIMAL(12,2)；0 视为未报价 |
| 10 | 是否涉及定制化 | 单选 是/否 | 是 | — | 固定两项，不进字典 |

## 四、数据表（新增 1 张，进 `database/init.sql` 与 `tools/gen_init_sql.php`）

```sql
CREATE TABLE IF NOT EXISTS `lost_order` (
  `id` INT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
  `lost_no` VARCHAR(32) NOT NULL COMMENT '输单编号（SD+时间戳）',
  `customer_name` VARCHAR(120) NOT NULL COMMENT '客户名称',
  `lost_at` DATETIME NOT NULL COMMENT '丢单时间',
  `loss_type_id` INT UNSIGNED DEFAULT NULL COMMENT '输单类型字典ID',
  `loss_type_name` VARCHAR(60) DEFAULT NULL COMMENT '输单类型名称（快照）',
  `industry_id` INT UNSIGNED DEFAULT NULL COMMENT '所属行业字典ID',
  `industry_name` VARCHAR(60) DEFAULT NULL COMMENT '所属行业名称（快照）',
  `company_scale_id` INT UNSIGNED DEFAULT NULL COMMENT '企业规模字典ID',
  `company_scale_name` VARCHAR(60) DEFAULT NULL COMMENT '企业规模名称（快照）',
  `loss_stage_id` INT UNSIGNED DEFAULT NULL COMMENT '丢单阶段字典ID',
  `loss_stage_name` VARCHAR(60) DEFAULT NULL COMMENT '丢单阶段名称（快照）',
  `budget_match_id` INT UNSIGNED DEFAULT NULL COMMENT '预算匹配字典ID',
  `budget_match_name` VARCHAR(60) DEFAULT NULL COMMENT '预算匹配名称（快照）',
  `remote_demo` TINYINT NOT NULL DEFAULT 0 COMMENT '是否远程演示：1是 0否',
  `customized` TINYINT NOT NULL DEFAULT 0 COMMENT '是否涉及定制化：1是 0否',
  `final_quote` DECIMAL(12,2) DEFAULT NULL COMMENT '最终报价（元）',
  `customer_choice` VARCHAR(500) DEFAULT NULL COMMENT '客户最终选择',
  `reason` TEXT NOT NULL COMMENT '输单原因描述',
  `salesman_id` INT UNSIGNED NOT NULL COMMENT '业务员ID',
  `salesman_account` VARCHAR(64) NOT NULL COMMENT '业务员账号',
  `salesman_name` VARCHAR(60) NOT NULL COMMENT '业务员姓名',
  `department_id` INT UNSIGNED DEFAULT NULL COMMENT '所属部门ID',
  `department_name` VARCHAR(60) DEFAULT NULL COMMENT '所属部门名称（快照）',
  `created_at` DATETIME NOT NULL COMMENT '提交时间',
  `updated_at` DATETIME DEFAULT NULL COMMENT '最近更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_lost_no` (`lost_no`),
  KEY `idx_lost_at` (`lost_at`),
  KEY `idx_lost_salesman` (`salesman_id`),
  KEY `idx_lost_type` (`loss_type_id`),
  KEY `idx_lost_stage` (`loss_stage_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='输单记录';
```

- 字典名称做**快照**（与 `dev_request.module_name` 同一做法）：字典改名/停用不影响历史单据展示与统计口径。
- 种子数据：`INSERT INTO \`dict_item\` ... ON DUPLICATE KEY UPDATE`（`uk_dict_type_name` 保证可重复执行）+ 5~8 条演示输单（`uk_lost_no` 保证幂等）。
- 变更流程按规范 §5.2：迁移脚本 `tools/migrate_lostorder.php` + `init.sql` + `gen_init_sql.php` 三处同步。

## 七、页面设计（全部复用现有实现逻辑）

### 7.1 输单登记 `LossCreateView.vue`
- 布局照 `IssueCreateView.vue`：左「moon-card」表单，字段布局同「问题提交」；提交前 `ElMessageBox.confirm`，成功后跳列表并高亮新记录（`store.highlightId`）。

### 7.2 输单列表 `LossListView.vue`
- 完整照 `IssueListView.vue`：顶部快捷时间范围 + 展开/折叠筛选区（记忆折叠状态）、`el-table` + `ColumnConfig` 列配置 + `useColumnWidths` 列宽记忆、`filteredOut` 提示条、Excel 导出（`xlsx`，文件名 `输单列表_YYYYMMDD_HHmm.xlsx`）、空状态插画。
- 列：编号、客户名称、丢单时间、输单类型、丢单阶段、所属行业、企业规模、预算匹配、最终报价、远程演示、定制化、客户最终选择、业务员、部门、输单原因（截断+tooltip）、操作。
- 销售员不显示"删除"（服务端同样校验）。

### 7.3 输单分析 `LossAnalysisView.vue`
- 照 `ReportsView.vue`：顶部时间范围（今日/近 7 天/近 30 天/本月/自定义，默认近 30 天）+ 维度筛选；每张卡右上角 tooltip 写统计口径（`config/metricTips.ts` 同款）。
- 卡片与图表（全部用 `components/charts/` 现成组件，不裸用 ECharts）：
  1. **概览**（`MetricCard`）：输单总数、报价总额、平均报价、远程演示占比、定制化占比、涉及客户数
  2. **输单类型分布**（`PieChart`）+ 类型占比表
  3. **丢单阶段分布**（`RankBarChart` / 柱）
  4. **所属行业 Top**（`RankBarChart`）
  5. **企业规模 / 预算匹配分布**（`PieChart`）
  6. **丢单趋势**（`TrendLineChart`，按日/月：输单数 + 报价金额）
  7. **交叉分析**：丢单阶段 × 输单类型（`StackedBarChart`）
  8. **是否远程演示 / 是否定制化 对输单类型的影响**（`StackedBarChart`）
  9. **业务员 / 部门输单排行**（`RankBarChart`，含单量与金额切换）
- 空数据统一出 `EmptyIllustration`；销售员页头提示"当前仅统计本人输单"。

## 十三、v2.7.1 修复记录（2026-10-23）

**问题**：输单登记页控件高度不一致——单行输入框 36px，下拉框只有 32px，差 4px。

**根因**：Element Plus 把 `.el-select__wrapper` 的 `min-height` 写死 `32px`（`padding:4px 12px; line-height:24px`），
而 `.el-input` 用的是 `--el-input-height: var(--el-component-size)`；本项目 theme 把 `--el-component-size` 提到 36px，
于是「文本输入框 36 / 下拉 32」天然错位。登录页看起来一致是因为那里用了 `size="large"`（44px）。

**修复**：`frontend/src/styles/theme.css` 增加一条 token 对齐规则（默认尺寸下拉框跟随 `--el-component-size`，
large/small 保持 EP 原样）。全局生效——用户管理、问题列表等筛选区的下拉也一并从 32 → 36，与同行输入框齐平。
改 token 即可整体升降，不再各页面单独写死高度。

**上线**：v2.7.1 静态产物 + `index.html` 上传，旧产物备份后删除。线上实测（headless Chrome 量取）：
客户名称 / 丢单时间 / 输单类型 / 丢单阶段 / 所属行业 / 企业规模 / 最终报价 / 预算匹配 / 客户最终选择 **全部 36px**；
输单列表筛选区 3 个下拉同样 36px；用户管理、问题列表的 select / input 均 36px。

## 十四、v2.7.2 新增：登记页天气（2026-10-23）

**需求**：输单登记页右侧「今天」卡片，在日期旁展示天气、气温等信息。

**实现**
- 后端 `site/api_handlers/weather.php`，路由 `weather/today`（需登录）：
  - 服务端直连 **Open-Meteo**（免费、无需 key）：`geocoding-api` 解析城市坐标 → `api` 取当前天气与当日高低温；
  - 城市取 `.env` 的 `WEATHER_CITY`；未配置返回 `available=false`，页面不显示天气块；
  - 结果缓存 30 分钟（`site/runtime/weather_cache.json`，含城市坐标缓存）；线上实测二次请求 18ms；
  - curl 优先（4s 连接 / 6s 总超时），SSL 校验证书失败时降级重试；任何异常都返回 `available=false`，接口绝不 500，**不阻塞登记**。
- 前端：`api/weather.ts`（静默请求）+ 登记页右侧卡片：日期带星期，下面一行「emoji + 气温 + 天气」，
  再一行「城市 · 今日最高/最低」，再一行「体感 / 湿度 / 风速」。
- 天气现象按 WMO 代码映射为中文（晴 / 多云 / 阴 / 雾 / 小雨 / 雷阵雨 / 雪…）。

**上线**：后端 2 个文件 + 静态产物 + `index.html` 上传；线上 `.env` 追加一行 `WEATHER_CITY=北京`（原键值逐字节校验未被改动）。
线上实测：卡片显示「☀️ 16°C 晴 / 北京 最高 16° 最低 7° / 体感 13° 湿度 53% 风 11 km/h」，控制台无异常，控件高度仍全部 36px。

> ⚠️ 打包注意：`WEATHER_CITY` 属开发期自加配置，按规范「打包时包内 .env 只保留数据库键」，导出打包时要清空。
